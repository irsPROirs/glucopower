# 1.19 — компактный экран и фиксированная минимальная реклама CPS

По запросу пользователя мощность всегда использует пакетA: только1818, без имени/TX/scan response. Выбор экспериментального варианта остаётся для ЧСС/каденса. Предпочтение пользователя не перезаписывается переключением профиля. CPS Measurement Notify получил PERMISSION_READ (не PROPERTY_READ), Feature.value=00000000, Location.value=05 и Measurement.value=00000000 инициализированы. Ответы onCharacteristicReadRequest с offset и уведомления только после CCCD уже существовали и сохранены. Формат93=00005D00. SensorLocation сохранён, хотя в присланном примере его нет.

Проверен XML https://github.com/oesmith/gatt-xml/blob/master/org.bluetooth.service.cycling_power.xml . Это описание стандартного сервиса, не алгоритма фильтрации GEOID. Само присваивание characteristic.value не отвечает клиенту: наш sendResponse сохранён. Нет оснований объявлять PERMISSION_READ обязательным для Notify на всех Android. ACCESS_FINE_LOCATION не добавлен: приложение не выполняет BLE-сканирование. Утверждения «телефон всегда Appearance0040», «Android тихо отсекает UUID», «GEOID ориентируется исключительно на UUID» не установлены нашими данными. Ранее рекламировался только выбранный профиль, а вариантA уже не обнаруживалсяCC600; текущая версия не выдаётся за подтверждённое исправление совместимости.

UI: главный экран без ScrollView; удалены заголовок/слоган, уменьшены отступы и высота кнопок. Значение глюкозы и источник/время расположены в одной карточке рядом; тесты/настройки по-прежнему в отдельном прокручиваемом диалоге. На реальном vivo и при экстремальном системном масштабе шрифта требуется проверка.

Проверки: полная assembleDebug/testDebugUnitTest/lintDebug успешно; дополнительный MainActivityTest подтверждает отсутствие ScrollView и размещение всех главных кнопок в границах360x640 тестового layout.
