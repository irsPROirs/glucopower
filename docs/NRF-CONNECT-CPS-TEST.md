# Независимая проверка обнаружения мощности через nRF Connect

Цель — проверить тот же vivo или Redmi как BLE-передатчик с другой реализацией
GATT-сервера. Проверка не гарантирует совместимость CC600 и сама по себе не
доказывает, что причиной отказа является прошивка компьютера.

1. Остановить трансляцию GlucoPower. На телефоне, который будет датчиком, использовать
   именно GATT Server и Advertiser nRF Connect, а не вкладку клиента подключённого
   устройства. Отключить остальные тестовые трансляции nRF Connect.
2. Создать один Primary Service `00001818-0000-1000-8000-00805f9b34fb`.
   В нём задать следующие характеристики и значения:

| Характеристика | Свойства | Начальное значение, HEX |
| --- | --- | --- |
| Cycling Power Measurement `2A63` | Notify | `00 00 5D 00` — только мощность 93 Вт |
| Cycling Power Feature `2A65` | Read | `00 00 00 00` |
| Sensor Location `2A5D` | Read | `05` — Left Crank |

Для `2A63` нужен единственный Client Characteristic Configuration Descriptor
`2902`, Read/Write. Если редактор nRF Connect уже добавил его автоматически,
второй добавлять не нужно. Начальное состояние CCCD — `00 00`; клиент включает
уведомления записью `01 00`.

3. Применить конфигурацию GATT-сервера. Создать connectable legacy-рекламу с
   16-битным Service UUID `1818` в основном ADV. Имена пунктов редактора могут
   отличаться между версиями nRF Connect; важны эти параметры, а не название шаблона.
4. Запустить рекламу. При необходимости проверить вторым телефоном, что в пакете
   действительно присутствует `1818`, а в GATT видны все три характеристики.
   После проверки отключить второй телефон от сервера, чтобы не спутать его
   события с обращениями CC600.
5. На CC600 удалить только старую запись тестируемого телефона как датчика,
   затем запустить новый поиск мощности. Телефон оставить с включённым экраном.
6. Сохранить результат поиска и серверный журнал nRF Connect: был ли запрос
   соединения, чтения GATT, запись CCCD. Для проверки передачи после подписки
   отправить уведомление `00 00 5D 00` средствами сервера nRF Connect. Изменение
   локального значения без отправки уведомления не подтверждает передачу клиенту.

Для отправки подготовлен [макрос 93 Вт](nrf-connect/cps-93w-macro.xml) по
[документированному формату Nordic](https://github.com/nordicsemi/Android-nRF-Connect/blob/main/documentation/Macros/README.md#send-notifications).
Импортировать его в nRF Connect и запускать после настройки сервера, рекламы
и подписки CC600. Для повторения включить режим Loop: макрос отправляет одно
уведомление и ждёт секунду. Он не создаёт GATT-сервис и не включает рекламу.
Файл проверен на корректность XML; импорт и радиообмен на телефоне здесь не проверены.

Если CC600 обнаружит и использует этот сервер, нужно сравнить его рекламу,
порядок регистрации и ответы ATT с GlucoPower на том же телефоне.
Если оба приложения не обнаруживаются, общего совпадения «Android-смартфон»
недостаточно для точного диагноза: остаются параметры платформенного Bluetooth,
идентичность/кэширование и совместимость поиска CC600. Отличие от GlucoPower
тогда не подтверждено. Для разграничения нужны события подключения и HCI-трасса.

Ссылки: [спецификация CPS](https://www.bluetooth.com/specifications/specs/cycling-power-service/),
[официальная документация nRF Connect](https://github.com/nordicsemi/Android-nRF-Connect).
Nordic подтверждает поддержку GATT Server и Peripheral advertising, но не
гарантирует совместимость пользовательской конфигурации с конкретным CC600.
