независимая от UI обработка BLE. Отказ обнаружения CPS и отсутствие входящего
LE-соединения vivo в старых трассах этими изменениями пока не объяснены.

## Исходная попытка после обновления vivo

До установки 1.12 проверить уже установленную 1.11 на Android 17. Сохранить
полную строку прошивки, Android/API, время и результат двух отдельных попыток:
POWER_TEST 93 и HEART_TEST 93. Каждая попытка поиска — минимум 60 секунд,
профиль внутри неё не менять. Для нового типа датчика удалить только старую
запись тестируемого телефона на CC600. Реальные датчики не удалять.

Сборщик теперь отдельно сохраняет runtime release/sdk и display firmware;
donor fingerprint не определяет версию Android. Использовать уже подготовленный
`tools/collect-ble-diagnostics.ps1`, HCI включать до попытки. Новый сбор здесь
автоматически не запускался; предыдущий отказ проверки разрешений ADB не обходился.

## Проверочная версия

Установить `GlucoPower-1.12-debug.apk` поверх прежней локальной сборки. Сначала
использовать прежние параметры рекламы. Отдельно проверить на Redmi Android 16
и vivo Android 17:

| Проверка | Критерий |
| --- | --- |
| Тест мощности | CC600 находит мощемер, включает CCCD, показывает 93 Вт минимум 60 секунд |
| Тест ЧСС | CC600 находит HR-датчик, включает CCCD, показывает 93 минимум 60 секунд |
| Реальная глюкоза через мощность | После смены test → live в том же профиле показание соответствует глюкозе и выбранному масштабу |
| Реальная глюкоза через ЧСС | Показание соответствует глюкозе ×10; это не физиологическая ЧСС |
| Нет входных данных | Живой режим показывает ожидание, не выдаёт тестовые 93 за глюкозу |
| Переподключение | После выключения/включения CC600 передача возобновляется; для bonded-клиента допустимо CCCD RESTORE, для non-bonded нужна новая запись CCCD |
| Фон | 15 минут с выключенным экраном, несколько обновлений входной глюкозы и продолжающиеся отправки |

Сохранить время, результат на экране CC600 и диагностику. «Android завершил»
не является доказательством отображения на CC600. Связь другого Bluetooth-
приложения также не является подпиской GlucoPower.

Если нет обнаружения, повторить отдельную попытку с галочкой «Диагностика:
UUID только в ADV, имя только в scan response». Другие настройки не менять;
профиль зафиксировать на всю попытку. Длинное имя до 29 байт UTF-8 помещается
в такой scan response, более длинное исключается из рекламы. Это не влияет
на обязательный UUID в основном пакете. Галочка сохраняется между запусками.

Если входящего соединения всё ещё нет, сначала проверить независимый
[CPS-сервер nRF Connect на Redmi](NRF-CONNECT-CPS-TEST.md), а не менять байты
измерений. Если сервер работает с CC600 — сравнить его HCI с GlucoPower.
Если не работает — поддержка/фильтрация BLE CPS данным CC600 требует эталонного
BLE-мощемера или подтверждения производителя; отсутствие успеха не доказывает ANT-only.

## Следующий этап интерфейса

После подтверждения четырёх режимов на CC600: Jetpack Compose, Material 3
Expressive, светлая/тёмная тема, динамические цвета с бирюзовой резервной палитрой.
Главный экран показывает глюкозу, источник, возраст данных и фактически
передаваемое значение. Выбор профиля и теста раздельный, управление запуском
одно; параметры рекламы и журнал находятся в диагностике. Immutable UI state
получается от службы, пересоздание Activity не перезапускает BLE. После UI-
изменений повторяются проверки радиообмена, фона, крупного шрифта и TalkBack.
Этот этап пока не выполнен: аппаратного подтверждения ещё нет.
