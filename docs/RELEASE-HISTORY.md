## Версия 1.11: SDK 36, workflow и выбор рекламы

Сборка переведена на compileSdk 36 / Build Tools 36.0.0, AGP 8.10.1,
Gradle 8.14.3 и Kotlin 2.2.21. `targetSdk` остаётся 34. SDK 36 не является
обязательным для работы на Android 16 и не доказывает исправление BLE.

Из приложенного workflow перенесены постоянный debug-ключ через необязательный
`DEBUG_KEYSTORE_BASE64`, PR-проверки, отчёты, ограничение параллельных запусков и
prerelease вне PR. Тесты и lint остаются обязательными. Настройка ключа и команды:
[сборка и подпись](BUILD-AND-SIGNING.md).

В APK добавлен переключатель **«Имя телефона в основном BLE-объявлении»**.
По умолчанию он включён: UUID профиля и короткое имя телефона идут вместе в
основном legacy-пакете. При выключении имя идёт в scan response, как в 1.10.
Длинное имя автоматически переносится или исключается с учётом лимита 31 байт;
UUID выбранного профиля остаётся в обоих пакетах. Системное имя не меняется.
Выбор применяется после нажатия кнопки запуска/теста и сохраняется. Его смена
перезапускает GATT, поэтому старому клиенту требуется переподключение.

Для проверки включить **тест мощности 93 Вт**, провести новый поиск телефона
на CC600. Если его нет — выключить переключатель, снова нажать тест мощности
и повторить поиск. Профиль ЧСС между этими попытками не включать. Это сравнение
двух стандартных вариантов рекламы, а не подтверждённое устранение фильтра CC600.

Пустой Control Point не добавлен: при нулевых Feature и отсутствии процедур
управления он исключается спецификацией CPS. Appearance `0x0484` нельзя задать
через публичный Android AdvertiseData API. Удаление всех сопряжений по числу 44
также не обосновано. Права GATT/CCCD, foreground-сервис и API отправки уже
соответствуют относящимся к ним рекомендациям.

Проверено: APK 1.11 собран, 51 тест пройден, Android Lint — 0 ошибок и 28
предупреждений. Сертификат подписи совпадает с локальным APK 1.10. Изменения

пояснение, что общие LINK-события могут относиться к другим приложениям.

После установки 1.10 запустить **«Тест мощности: постоянно 93 Вт»**, удалить старую
запись телефона из датчиков CC600 и провести новый поиск мощности с CC600.
Не переключать профиль во время этой проверки. Открыть страницу поездки,
подождать 30–60 секунд и сохранить диагностику. Если мощность не появляется,
нужна HCI-трасса попытки; ещё один LINK не объяснит фильтрацию CC600.
Порядок: [исследование и сбор трассы](BLE-ANDROID16-CC600.md).

Удаление исходящего подключения исправляет ошибочный сценарий приложения.

## Версия 1.9: сохраняемый тест мощности и фактический этап передачи

Новый журнал Redmi 8 показывает минуту рекламы мощности без обращения CC600,
затем подключение CC600 к ЧСС, подписку и 23 успешных тестовых отправки без ошибок.
Это журнал сервера Redmi; причину отдельного отказа сервера vivo он не устанавливает.

Исправлены два обнаруженных дефекта приложения:

* Отчёт больше не печатает безусловное «Нет GATT ACCESS/WRITE CCCD от CC600».
  Он перечисляет фактических клиентов GATT и подписчиков, показывает источник/время
  входного измерения и различает ожидание клиента, подписки и данных xDrip+/GDH.
  Значение глюкозы в общий журнал не записывается.
* Кнопка теста мощности включает отдельный сохраняемый режим `POWER_TEST` с 93 Вт.
  Он восстанавливается после пересоздания службы, не зависит от входной глюкозы
  и настройки масштаба и не подменяет последнее реальное измерение. Переход между
  тестом и живой мощностью сохраняет GATT-сервис и подписку; ожидающие тестовые
  пакеты удаляются. Уже переданный Android пакет может завершиться.

Для проверки установить 1.9 на vivo, включить **тест пульсометра 93**, подключить
CC600 и через 30–60 секунд скопировать диагностику именно с vivo. Затем отдельно
повторить **тест мощности 93 Вт**. Пока нет обращения CC600 к профилю мощности,
изменение формата отправляемого значения не проверяет причину отказа обнаружения.
Новый режим теста исправляет его восстановление, но не доказывает совместимость
поиска мощности CC600 с Android.
Проверено: APK собран, 42 теста пройдены, Lint — 0 ошибок (17 предупреждений).

## Версия 1.8: обработка ATT и завершение соединений по образцу Nordic

После сверки с серверной частью Nordic BLE Library:

* Остановка отменяет только соединения, которые приложение явно удерживало через
  `connect(device, false)`. Наблюдение callback подключения не считается владением
  соединением и больше не служит основанием для `cancelConnection()`.
* На Execute Write и Cancel приходит ответ `GATT_SUCCESS`: все prepared writes
  отклоняются заранее, а выполнение или отмена пустой очереди по ATT завершается
  успешно. Подписки при этом не меняются. Клиент получает ATT-ответ вместо ожидания
  тайм-аута из-за отсутствующего обработчика.
* Запись CCCD неправильной длины получает `GATT_INVALID_ATTRIBUTE_LENGTH`.

`heart_rate_monitor` реализует BLE-клиент для чтения ЧСС, а Nordic `BLE-COMMON.md` —
парсеры входящих данных. Их код сканирования и подписки не относится к рекламе
телефона как мощемера. Полезные серверные приёмы перенесены без добавления новой
зависимости. Подробности и ссылки: [сравнение реализаций](COMPARISON-POWER-METERS.md).

Эти изменения исправляют работу уже установленного соединения и ATT-запросов.
Причина отсутствия vivo в поиске мощности CC600 ими не установлена.
Проверено: сборка APK, 38 тестов, Lint — 0 ошибок (17 предупреждений).

## Версия 1.7: совместимость CC600 и раздельная диагностика соединения

По присланным фото vivo передал Redmi пакет мощности `00 00 5D 00` (93 Вт).
Текстовый журнал содержит рекламу `0x1818`, а не обмен GATT с CC600.
Поэтому отсутствие показаний CC600 пока нельзя приписать кодированию CPS или
общему запрету BLE на Android 16.

* Приложение удерживает используемое GATT-соединение через `connect(device, false)`
  при обращении клиента к его характеристикам. Повторные обращения не создают
  повторных запросов, если Android уже принял запрос на удержание.
* Обращение к характеристике или CCCD теперь учитывается как доказанное соединение,
  даже если прошивка не передала отдельный callback состояния связи.
* Кнопка **«Повторить соединение с CC600»** позволяет выбрать сопряжённый или уже
  подключённый велокомпьютер и запросить присоединение GATT-сервера к его соединению.
  Принятие этого запроса не выдаётся за соединение или подписку.
* UUID выбранного профиля повторяется в scan response, чтобы он присутствовал
  в обоих видах пакетов; имя остаётся только в scan response и проверяется по
  оставшимся 25 байтам. Польза для конкретной прошивки CC600 требует проверки.
* Диагностика различает системные ACL, обращения к GATT, подписку CCCD и завершения
  отправки. Записываются события bond/потери ключей Android 16. Чужие ACL, сохранённая
  пара и запрос на подключение не создают подписку на измерения.

Подробное исследование первичных источников Android, AOSP, Bluetooth SIG и Nordic,
разбор вложений и порядок проверки: [BLE-ANDROID16-CC600.md](BLE-ANDROID16-CC600.md).

После смены ЧСС на мощность **удалите только старую запись датчика телефона на CC600**
и добавьте его заново как мощность. Если Android сообщает об ошибке ключей, удалите
именно пару CC600 на обеих сторонах и повторите сопряжение. Сначала проверьте тест
93 Вт с включённым экраном vivo, затем реальную глюкозу и выключенный экран.
В режиме мощности приложение публикует только фитнес-сервис CPS, сохраняя свободными
ЧСС и каденс. Системные GATT-сервисы vivo не контролируются приложением.

Проверено: `assembleDebug testDebugUnitTest lintDebug`, **34 теста**, 0 ошибок Lint.
Обнаружение мощности и отображение показаний на физическом CC600 пока не подтверждены;
версия 1.7 исправляет управление связью и учёт её состояния, но не доказывает устранение
неизвестного ограничения прошивки CC600.

## Версия 1.6: восстановление отправки и приём GDH

Исходники приложения теперь находятся в `app/`; GitHub Actions собирает их напрямую,
вместе с регрессионными тестами и Android Lint. YAML больше не генерирует другую копию кода.

* Основной legacy BLE-пакет содержит только UUID выбранного сервиса (для мощности — `0x1818`);
  имя телефона передаётся в scan response, если укладывается в 31 байт.
* Добавлен Device Information Service с производителем и моделью. Реклама запускается
  после успешной последовательной регистрации обоих GATT-сервисов.
* Если Android принял уведомление, но не вызвал `onNotificationSent` за 10 секунд,
  приложение закрывает GATT-сеанс и через 2 секунды запускает новый. Клиенту потребуется
  переподключиться и заново подписаться. Запоздалые callbacks старого сеанса игнорируются.
* Приём GDH/Juggluco исправлен по [описанию полей GDH](https://github.com/pachi81/GlucoDataHandler/blob/master/TASKER.md):
  используются `mgdl` и `Time`, а не только ошибочные ключи с префиксом `glucodata.Minute.`.
  Значение `glucose` не используется для угадывания единиц. Новое измерение сразу ставится в очередь BLE.

Проверка на vivo X300 / Android 16: установите 1.6, разрешите Bluetooth и фоновую работу,
нажмите **«Тест: отправить 9.3 ммоль/л (93 Вт)»**, добавьте телефон именно как датчик мощности
и откройте поле мощности в поездке. Счётчик «Android завершил» должен расти каждую секунду.
Затем включите обычную передачу мощности и трансляцию GDH/xDrip; проверьте изменение
значения после нового измерения и при выключенном экране. Профиль мощности не занимает ЧСС или каденс.

Эта версия устраняет выявленные ошибки приложения, но обнаружение мощности и отображение данных
на физическом CC600 пока не подтверждены. При неудаче сохраните диагностику после 20–30 секунд
теста: она отличает отсутствие обнаружения, отсутствие подписки и зависание отправки Android.

Локальная сборка (JDK 17, Android SDK 34, Gradle 8.5):
`gradle assembleDebug testDebugUnitTest lintDebug --no-daemon`.
Проверено локально: сборка успешна, 30 тестов пройдены, Lint — 0 ошибок (13 предупреждений).

Android-приложение («прослойка»), которое принимает текущий уровень глюкозы из **xDrip+** или **GlucoDataHandler** и транслирует его по Bluetooth Low Energy (BLE) на велокомпьютер **Geoid CC600** под видом **датчика мощности (Cycling Power, 0x1818)**.

Например, сахар **9.3 ммоль/л** отображается на велокомпьютере в поле мощности как **93 Вт (W)**.

## Как собрать APK

### Вариант 1: Через Android Studio на компьютере
1. Распакуйте архив `GlucoBLE_Power_Project.zip`.
2. Откройте папку `GlucoBLE_Power_Project` в **Android Studio**.
3. Дождитесь окончания синхронизации Gradle и выберите в верхнем меню **Build → Build Bundle(s) / APK(s) → Build APK(s)**.
4. Установите готовый файл `app-debug.apk` на телефон.

### Вариант 2: Без установки Android Studio (через GitHub прямо с телефона)
1. Создайте бесплатный приватный репозиторий на GitHub и загрузите туда файлы из архива.
2. Перейдите во вкладку **Actions** → запустите **Build GlucoBLE Power APK**.
3. Через 2 минуты скачайте готовый `app-debug.apk` в разделе **Artifacts**.

## Обновление 1.1: BLE, фон и уведомление

- Реклама профиля Cycling Power (`0x1818`) начинается после регистрации GATT-сервиса. UUID находится в основном рекламном пакете. В версии 1.2 имя телефона также включается в основной пакет, если занимает не более 22 байт UTF-8; более длинное имя до 29 байт включается в scan response. В поиске CC600 датчик может отображаться под именем телефона или Bluetooth-адресом.
- Экран показывает фактический статус BLE и ошибки запуска. Поддерживается чтение дескриптора подписки CCCD, необходимое некоторым BLE-клиентам.
- Иконка приложения — капля с молнией; в шторке указаны глюкоза, время измерения и статус BLE. Через 15 минут без свежего измерения появляется соответствующая пометка. Повторный ответ локального HTTP-сервера не меняет время измерения.
- Foreground-сервис удерживает CPU во время трансляции при выключенном экране. Это расходует батарею; кнопка «Остановить трансляцию» освобождает удержание. После перезапуска сервиса восстанавливаются последнее измерение, его время и настройка масштаба.

### Проверка на vivo X300 Ultra и Geoid CC600

1. Установите APK, разрешите Bluetooth/«Устройства поблизости» и уведомления. После предоставления разрешений при необходимости повторно нажмите «Запустить».
2. В xDrip+ оставьте включённой локальную трансляцию. Если задан конкретный получатель, укажите `com.example.glucoble` либо очистите список получателей. Полученные из xDrip+ значения всегда переводятся из mg/dL в mmol/L, независимо от единиц на экране xDrip+.
3. Нажмите в GlucoPower «Разрешить работу в фоне (батарея)» и подтвердите системное разрешение. В настройках vivo разрешите для GlucoPower автозапуск и фоновую работу без ограничений энергосбережения. Проверьте ограничения также у xDrip+. Названия и расположение этих пунктов зависят от версии OriginOS/Funtouch OS.
4. Запустите трансляцию. Дождитесь статуса «датчик мощности доступен для поиска (0x1818)». На CC600 ищите Bluetooth-датчик **мощности**, не пульса. Проверьте соответствие: `8,4 mmol/L → 84 W`.
5. Выключите экран телефона на 10–15 минут. После нового измерения xDrip+ должны обновиться мощность на CC600 и время измерения в шторке. Если нет — запишите статус BLE, время измерения и версию Android/OriginOS.

Без физического телефона и CC600 можно проверить сборку и кодирование данных, но нельзя подтвердить обнаружение и работу Bluetooth в фоне на конкретном устройстве. В CI выполняются `assembleDebug` и `testDebugUnitTest`: тестируются единицы глюкозы, масштаб мощности, байты Cycling Power, ограничения имени в scan response и обработка времени измерений.


## Версия 1.2: проверка обнаружения CC600

Android-сообщение «реклама запущена» подтверждает успех локального API, но не доказывает, что CC600 увидел датчик. Работа Heart for Bluetooth на часах подтверждает приём профиля пульсометра `0x180D` с часов; для приложения на телефоне нужны отдельные проверки.

В версии 1.2 убрана проверка поддержки **нескольких** рекламодателей как обязательного условия для **одного** BLE-датчика, имя короткого телефона передаётся вместе с UUID в основном рекламном пакете, добавлен тайм-аут запуска 20 секунд и отдельные счётчики соединений и подписок. На Android 13+ передача выполняется через API уведомлений с отдельным массивом байтов, без общей изменяемой характеристики.

1. Убедитесь, что экран показывает **GlucoPower 1.2**, запустите обычный датчик мощности и ищите на CC600 датчик **мощности по Bluetooth**. Для исключения фильтра по имени временно можно вручную задать короткое Bluetooth-имя телефона, например `GlucoPower`, до запуска трансляции. Приложение само системное имя не меняет.
2. Если CC600 не находит мощность, нажмите **«Диагностика BLE: тестовый пульсометр 93»**. Остановите Heart for Bluetooth на часах, чтобы не перепутать устройства, затем ищите на CC600 **пульсометр** от телефона. Тест передаёт постоянные 93 уд/мин — это не реальные данные пульса или глюкозы.
3. Если пульсометр телефона виден, а мощность нет, это сужает проблему до совместимости/фильтрации профиля мощности, а не общего отсутствия BLE-рекламы телефона. Это ещё не доказывает отсутствие поддержки BLE-мощности в прошивке CC600. Если не виден ни один профиль, нужны проверка рекламы вторым телефоном (например, nRF Connect) и информация о прошивке CC600.
4. После проверки нажмите **«Запустить датчик мощности»**: пульсометр выключится, останется профиль мощности `0x1818` с глюкозой ×10. Диагностический режим не заменяет основной режим и помечен в уведомлении.

При проблеме запишите версию приложения, полную строку BLE, число соединений/подписок и результаты поиска обоих профилей. Без этих результатов нельзя достоверно назвать причину несовместимости конкретной пары vivo/CC600. В CI версии 1.2 выполняются 7 unit-тестов; физическое обнаружение требует проверки на устройстве.

## Версия 1.3: передача измерений и журнал BLE

По результатам проверки на vivo X300 Ultra и CC600 с прошивкой **1.408** пульсометр телефона обнаруживается и сохраняется, но показания не поступают; датчик мощности не обнаруживается. Счётчики **0 подписок / 1 соединение** не подтверждают подключение CC600: соединение может принадлежать другому устройству. Сохранение датчика в списке также не подтверждает подписку на измерения.

Исправлена очередь отправки: следующий пакет ждёт `onNotificationSent` от Android, накопленные измерения заменяются последним. После успешного ответа на запись CCCD сразу отправляется первое измерение. Ошибки отправки и отсутствие завершения за 10 секунд видны в диагностике. Успешное завершение Android не доказывает отображение значения на CC600.

Кнопка **«Скопировать диагностику BLE»** копирует последние 100 событий: запуск рекламы, соединения с именами клиентов (если Android их знает), чтения характеристик, запись CCCD, подписки и результаты отправки. Журнал хранится в памяти службы, сохраняется при переключении профилей и не содержит значений глюкозы или Bluetooth-адресов. Часы отключать от телефона для получения журнала не требуется.

Для проверки:

1. Установите версию **1.3**, включите тестовый пульсометр 93 и подключите сохранённый датчик телефона на CC600. Откройте экран поездки с полем ЧСС, подождите 15 секунд, скопируйте диагностику из GlucoPower и сохраните текст. Тестовые 93 — условное значение, не настоящий пульс.
2. Переключитесь на обычный датчик мощности, повторите поиск **мощности** на CC600 и скопируйте второй журнал. Передайте оба текста при сообщении об ошибке.

Совместимость с CC600 1.408 пока не подтверждена. Очередь устраняет нарушение порядка отправки, но сама по себе не объясняет отсутствие обнаружения или подписки. Журнал позволяет установить, на каком этапе останавливается обмен, вместо предположений по общему числу соединений.

В сборке выполняются 19 тестов: кодирование и время измерений, очередь отправки и проверки обработчиков GATT через Robolectric/Mockito (подписка, порядок ответа и уведомления, смена профиля, ошибки Android, обновление мощности 84 → 93). Эти проверки не моделируют радиоэфир и прошивку CC600.

## Версия 1.4: глюкоза через поддерживаемый профиль ЧСС

Последующие проверки подтвердили: nRF Connect на Redmi получает от vivo измерение мощности `00 00 5D 00` (93 Вт). CC600 принимает тестовые 93 через профиль ЧСС **с Redmi 8**, но не с vivo; мощность с обоих телефонов не обнаруживается. Это подтверждает отдельные рабочие сценарии BLE, но не устанавливает причину несовместимости vivo/CC600 или фильтрации мощности.

Добавлен отдельный режим **«Глюкоза через ЧСС: ммоль/л ×10»**. Он использует Heart Rate Service `0x180D` и уведомления `0x2A37`, передавая текущие значения xDrip+/GDH. Например, **8,4 ммоль/л → 84 в поле ЧСС**, следующее измерение **9,3 → 93**. Масштаб в этом режиме всегда ×10, независимо от настройки мощности. Это условное представление глюкозы, не измерение пульса; на CC600 оно занимает поле ЧСС, в том числе в записи тренировки. Для проверки отключите трансляцию пульса с часов, чтобы CC600 использовал датчик телефона.

1. Установите 1.4, запустите **«Глюкоза через ЧСС: ммоль/л ×10»** и дождитесь реального измерения xDrip+ в приложении.
2. Подключите телефон на CC600 как датчик **ЧСС**. Если сохранился тестовый датчик того же телефона, подключите его; при необходимости повторите добавление датчика.
3. Сопоставьте значение на CC600 с глюкозой ×10 и проверьте изменение после следующего измерения с выключенным экраном телефона. В шторке показаны режим и время измерения.

Тестовый пульсометр с постоянными 93 остаётся отдельной кнопкой. Выбранный режим сохраняется для восстановления службы. Тест мощности больше не записывается как последнее реальное измерение; сохранённые тестовые значения старых версий не используются при переходе к передаче глюкозы. В режиме ЧСС передача ожидает измерения, если реальных данных ещё нет.

Переключение между тестовым пульсометром и глюкозой через ЧСС сохраняет GATT-сервис и подписку клиента. Ожидающие отправки тестовые пакеты удаляются из очереди; уже переданный Android пакет может завершиться. Переход между мощностью и ЧСС перезапускает BLE с другим сервисом.

Проверки 1.4: сборка APK и 24 теста, включая доставку xDrip-измерений 8,4 → 9,3 через ЧСС, кодирование 8/16 бит, ожидание реальных данных и переключение режима без потери подписки. Передача живой глюкозы на физическом CC600 требует проверки пользователем; успешный тест фиксированного ЧСС 93 не заменяет её.

Режим мощности остаётся доступен. Версия 1.4 предоставляет обходной путь через ЧСС, **не заявляет исправление обнаружения мощности на CC600 1.408**. Значения ЧСС до 255 кодируются в 8 бит, выше — в стандартном 16-битном формате без обрезания до 255; отображение расширенного диапазона зависит от принимающего устройства.

### Геолокация и результаты поиска

GlucoPower работает BLE-передатчиком/GATT-сервером и не сканирует окружающие датчики. Для используемых операций на Android 12+ нужны `BLUETOOTH_ADVERTISE` и `BLUETOOTH_CONNECT`, а не разрешение определения местоположения. Проверка выполнена по [исходникам BluetoothLeAdvertiser Android в LineageOS](https://github.com/LineageOS/android_packages_modules_Bluetooth/blob/lineage-23.0/framework/java/android/bluetooth/le/BluetoothLeAdvertiser.java). Связь разрешения геолокации со сканированием BLE в некоторых версиях Android не объясняет ситуацию, когда реклама и передача GlucoPower уже работают со вторым телефоном.

Повторный поиск 18.10.2026: запросы к Google, Bing, сайту GEOID и документации Bluetooth/Android были отклонены сетевым шлюзом среды (403). Поиск GitHub по `CC600 BLE` и `cycling power geoid` не дал относящихся к проблеме результатов. Поэтому достоверного вывода о поддержке BLE-мощности прошивкой 1.408 или готового исправления производителя нет. Наличие обязательных характеристик сервиса сверено с [описанием Cycling Power Service](https://github.com/oesmith/gatt-xml/blob/master/org.bluetooth.service.cycling_power.xml); это не подтверждение совместимости конкретного велокомпьютера.
