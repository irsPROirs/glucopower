# GlucoPower 1.13: продолжение без велокомпьютера

Работа выполнена по сохранённым трассам Android 16. Пользователь сейчас не
может проверить CC600; новые аппаратные проверки не являются условием сборки.
Результатов vivo после обновления до Android 17 пока нет.

## Изменения

Сохранены исправления 1.12: отдельный последовательный BLE-поток, очередь
уведомлений с ожиданием callback Android, сохранение принятых CCCD для bonded
клиентов отдельно по профилям. Без прежней подписки сопряжение не разрешает
передачу. Сохраняются четыре режима: глюкоза через мощность и ЧСС, тесты 93
для обоих профилей.

Минимальная реклама теперь включена по умолчанию: выбранный UUID 1818/180D
в основном legacy connectable пакете, имя только в scan response, без
повторения UUID. Это схема из you-gatt-me; регистрация наших обязательных
GATT-характеристик по-прежнему завершается до запуска рекламы. Она применяется
при обновлении с 1.11, где этой настройки не было. Если в 1.12 пользователь
явно сохранил другой вариант, его выбор сохраняется.

Источник и ограничения примеров: [разбор репозиториев](COMPARISON-NEW-REFERENCES.md).
Из Arduino-примера не перенесены ошибочный Feature и фиктивный каденс.
Изменение рекламы — проверяемая гипотеза совместимости, не подтверждённый
фикс обнаружения CC600.

## Проверка по старым трассам

`assembleDebug testDebugUnitTest lintDebug --offline --no-daemon` выполнены
успешно: 65 тестов, lint 0 ошибок / 29 предупреждений. APK
`GlucoPower-1.13-debug.apk`, versionCode 14, подписан тем же сертификатом, что
локальная версия 1.11; проверено apksigner. SHA-256:

```text
C7DB731FCA2D1EBEABCB0811461236DF2604B6111B814C3C41F06EAE7DDBB225
```

Добавлен регрессионный тест последовательности Redmi: соединение, шесть
чтений модели DIS, запись CCCD 0100, 12 уведомлений 00 5D, отключение.
До записи CCCD и после отключения уведомлений нет. Это воспроизведение
прикладных callback, а не эмуляция контроллера vivo или радиотест Android 16.
Также проверены новый вариант по умолчанию и сохранение явного выбора.

У vivo в основной старой трассе нет входящего LE-соединения CC600. Поэтому
эти данные не доказывают сбой очереди отправки или его устранение. На Redmi
CC600 после смены HRS на CPS повторно обнаруживает сервис, но не подписывается.
Пакеты CPS или дополнительные характеристики не могут заставить центральное
устройство установить соединение и подписку.

Аппаратная проверка четырёх режимов и фоновой работы остаётся на будущее.
Material 3 / Expressive остаётся следующим этапом после проверки основного
функционала согласно согласованному порядку работ.
