# Heart for Bluetooth: работающий у пользователя источник ЧСС

## Источник и уровень подтверждения

Пользователь подтвердил: приложение на его часах передаёт ЧСС на его CC600.
Это подтверждает работоспособность этой конкретной связки для HRS, но не
работоспособность CPS или BLE-периферии vivo.

Прислан документ `Ble Heart Rate Broadcast Spec.md`, сохранённый во вложении
`.codex-remote-attachments/01a15099-6b2e-7ab3-8983-17823bed2512/03f661db-b9da-4030-8825-63aa377b0913/1-Ble-Heart-Rate-Broadcast-Spec.md`.
Автор документа сообщает о разборе Heart for Bluetooth,
`lukas.the.coder.heartforbluetooth`, 5.5 / code 155, minSdk 29 / targetSdk 34.
Ни APK, ни байткод этого приложения здесь независимо не проверялись.
Версия приложения и ОС именно на часах пользователя отдельно не подтверждены.
Все детали реализации ниже — сведения из присланного документа.

## Полезные параметры и сравнение с GlucoPower 1.13

| Область | По присланной спецификации | Значение для проекта |
|---|---|---|
| Реклама | Connectable legacy, UUID 180D в ADV, имя только в scan response | Совпадает со структурой минимальной рекламы 1.13 |
| Настройки | TX MEDIUM, timeout 120000 мс; режим скорости рекламы явно не указан | В GlucoPower TX HIGH, LOW_LATENCY, timeout 0; возможные отдельные переменные будущего теста |
| Перезапуск рекламы | stopAdvertising, задержка 3000 мс, затем startAdvertising | Кандидат для проверки при проблемах повторного запуска, не установленная причина отказа vivo |
| GATT | PRIMARY 180D; 2A37 NOTIFY с permission READ; CCCD 2902 READ/WRITE | Базовая структура совпадает; READ permission не равнозначен свойству READ |
| Дополнительные атрибуты | 2A38 Body Sensor Location = 02 (wrist); 2901 User Description = HeartForBluetooth | В GlucoPower отсутствуют; необходимость для CC600 не доказана |
| Пакет | `00 HR`, UINT8, без контакта, энергии и RR | Тест 93 в GlucoPower также `00 5D` |
| Частота | Последняя ЧСС каждые 2000 мс, только подписчикам | В GlucoPower около 1000 мс; старая трасса Redmi подтверждает приём CC600 с этой частотой |
| Подписка | Отдельные connected/subscribed коллекции; CCCD 0100/0000, ответ при responseNeeded | Уже реализовано, новая связь сама по себе не разрешает notify |
| Потоки | Mutex/ReentrantLock, снимок списка клиентов | В GlucoPower последовательный BLE HandlerThread и очередь отправки |
| Фон | Foreground service connectedDevice | Уже есть необходимые разрешения и тип сервиса |
| Пауза | Останавливает таймер, сохраняет GATT и подписки | Полезный принцип для будущей паузы; не закрывать сервер при смене только источника данных |

## Что не переносить автоматически

* Описание объясняет задержку 3 секунды особенностями Bluetooth-стека, но не
  содержит сравнительных трасс. Нельзя считать её обязательной для всех
  Android-устройств или доказанным исправлением vivo.
* 120-секундное окно рекламы — выбор приложения для часов. Для длительного
  поиска и повторного подключения телефона оно может быть неудобно.
* Старый вызов notify с изменяемым characteristic.value не заменяет используемый
  в GlucoPower API 33+ с отдельным массивом и контролем завершения отправки.
* Игнорирование offset, возврат тестовой ЧСС 1 при чтении и упрощённая проверка
  descriptor writes из описания не являются образцом для наших обработчиков.
* Указанный в документе список runtime-запросов включает обычные разрешения
  WAKE_LOCK/FOREGROUND_SERVICE. Не трактовать весь список как разрешения,
  для которых нужен пользовательский диалог. BODY_SENSORS и требования
  watch/heartrate относятся к оптическому сенсору часов, не к трансляции глюкозы.
* Успех на часах не доказывает, что дополнительные дескрипторы или location
  обязательны: Redmi уже передавал ЧСС с минимальным профилем GlucoPower.

## Следующее применение

Сначала проверить неизменённую 1.13, как согласовано. Если потребуется,
сравнивать варианты по одной переменной: параметры рекламы, задержка повторного
старта, затем дополнительные HRS-атрибуты при наличии соединения. Отдельно
фиксировать discovery, CCCD и notify. Не объединять все отличия в один «фикс».
Код приложения по этому документу не менялся.
