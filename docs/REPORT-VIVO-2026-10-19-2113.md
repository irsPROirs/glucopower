# Попытка CC600 в 21:13: нет входящего LE-соединения

Источник: `diagnostics/20261019-211417-976`, пользователь указал тест
мощности 93 в 21:13. Модель V2547A, runtime Android 17,
PD2547E_A_17.1.10.1.W10 подтверждены файлами сборщика. ADB не запускался.

Из девяти HCI-файлов нужное окно содержит `hci-1-btsnoop.log`:
21:12:30.572–21:16:53.445, 13667 записей; SHA-256

ADV VPM 21:12:31.769 и callback .777. Как в прежнем vivo-файле, требуется
correction -3 / display +3; JSON с корректной зоной: `analysis/current-local.json`.
Нулевые drops/truncated records; есть неполный последний заголовок в конце
файла, после интересующей попытки. Первичные JSON с +00 — промежуточные,
их метку зоны не использовать как реальное UTC.

  undirected, LE 1M, 100–131.25 мс, все три канала, filter policy 0,
  RPA, выбранная мощность -7 dBm.
* Основной пакет 27 байт: Flags 02, Complete Local Name (15 байт), TX power,
  Complete 16-bit Service UUIDs с 1818. Scan response пустой.
* Все команды настройки и включения завершились status 0. В 21:12:46–47
  системный стек дважды отключает и снова включает оба advertising set;
  паузы около 8 и 5 мс. После этого нет отключения set 1 в оставшемся файле.
  Смена интервала других set не относится к GlucoPower.
* Единственное LE Connection Complete — 21:12:47.167, роль телефона central,
  после собственного outgoing Create Connection. Входящих peripheral LE
  соединений и неуспешных LE Connection Complete не обнаружено.
* ATT принадлежит этой исходящей связи. Нет discovery/CCCD от входящего
  клиента мощности. В 21:13 нет соединения, на котором можно было бы
  наблюдать чтение стороннего атрибута из предыдущего nRF-теста.
* Дополнительно проверены BR/EDR Connection Complete: три успешных и два

## Вывод

В этой попытке проблема возникает до GATT. Гипотеза зависшего стороннего
ATT-чтения из nRF-лога здесь не подтверждается. Контроллер принимает ожидаемую
рекламу CPS, сервер ранее реально передал 74 уведомления независимому клиенту.
Ни общий отказ notify vivo, ни ошибка формата CPS не объясняют этот поиск.

Host HCI не доказывает получение рекламных пакетов именно CC600 и не показывает
его фильтры сканирования. Следующее полезное наблюдение — свежий scan nRF
Connect во время того же поиска, с рекламным пакетом/UUID/адресом (без Connect),
и точный экран выбора типа/протокола датчика на CC600, версия его прошивки.
Поддержка BLE CPS именно этой прошивкой не установлена; не объявлять её
ANT-only без подтверждения. Код приложения по этому отчёту не изменён.
